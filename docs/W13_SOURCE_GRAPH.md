# W13 — C/C++/Rust source and symbol graph (offline)

**Status:** Proposed PR, not yet independently qualified. **Dependencies:** W12 is merged to `main`; no debugger, probe or external editor is started. Windows/Linux CTest and independent review remain acceptance gates.

## Implemented and explicitly not implemented

The workbench reads a **versioned user-supplied symbol/source sidecar**, checks the SHA-256 of a local ELF binary, then independently checks SHA-256 of each referenced source file before allowing **read-only jump to source** inside RTOS Observatory. It visualizes functions and explicitly **declared** CALL/LOCK relationships for C, C++ and Rust. It maps a numeric PC to a function only if the ELF digest matches and exactly one declared function address range matches.

The sidecar **does not extract or independently verify DWARF, call instructions, line tables, demangling, lock semantics or source relationships from ELF**. A matching ELF SHA-256 proves that the selected file bytes match the sidecar's claimed digest, **not** that sidecar function ranges, calls, source lines or resource operations are true. An attacker can forge both manifest and checksum. This package is a safe source graph and provenance foundation, not a qualified DWARF parser, run-time call graph, lock dependency proof or true cross-language code analyzer. W14 debugger, W15 safe target reads and later symbol/debug-info validation remain separate.

## Manifest v1

A bounded TSV text file starts:

```text
RTOS-OBSERVATORY-SYMBOLS<TAB>1<TAB>elf-sha256-lowercase<TAB>firmware-label<TAB>32|64
```

Records (tabs between fields):

| Type | Fields | Meaning |
| --- | --- | --- |
| `FILE` | relative POSIX-style path, SHA-256 lowercase | Declared source file digest |
| `FUNC` | id, `C/C++/Rust`, name, address hex, size hex, relative path, positive source line | **Declared** function interval and source relationship |
| `CALL` | caller id, callee id, source line | **Declared** call relationship; not observed run-time calls |
| `LOCK` | function id, resource id, `acquire/release/wait/other`, source line | **Declared** resource use; not proven ownership or a live lock |

The parser preserves physical manifest line numbers for every function/edge, rejects duplicates, unresolved references, invalid ranges, malformed hashes and unsupported languages. Default bounds: 1 MiB manifest, 4096 bytes/line, 512 files, 4000 functions, 10,000 CALL and 10,000 LOCK records; selected ELF max 256 MiB and source max 2 MiB per file. ELF check supports **little-endian ELF32/ELF64 header and SHA-256**, not machine or DWARF semantic validation. Source relative paths cannot be absolute, use drive letters, backslashes, `..` or escape the canonical selected root via symlink.

### Verified source navigation

1. Load sidecar + local ELF + local source root in **Source/symbol graph**.
2. If ELF SHA-256 and the selected source SHA-256 match, select a function and **Jump to declared function line**. The app reads the selected source file once under a 2 MiB cap, hashes **the same bytes that are displayed** and shows a small internal read-only source preview. No external application or user source file is modified.
3. Enter a decimal PC address (or inspect a W12 PC record with matching self-reported firmware/width labels) to select an *address-range candidate*. Ambiguous overlapping ranges or a missing ELF match refuse resolution. W12 firmware label alone is **never attestation** of shared capture/build identity.
4. Without identities, the graph shows source-declared links marked unverified and does **not** grant a source jump.

### CLI and evidence fixtures

```text
rtos-observatory-desktop --symbols path/to/symbols.tsv path/to/firmware.elf path/to/sources
rtos-observatory-desktop --smoke-symbols path/to/symbols.tsv path/to/firmware.elf path/to/sources
rtos-observatory-desktop --smoke-ui-symbols path/to/symbols.tsv path/to/firmware.elf path/to/sources
```

`observatory_symbol_identity` creates a deliberately **synthetic ELF header-only file**, source files in C/C++/Rust, and SHA-256-matched manifest under the build directory `w13-symbol-test-fixture`. It tests SHA-256 known-answer vectors, positive identity/navigation, altered ELF/source refusal, missing root, overlap ambiguity, unsupported formats, bad counts, paths, caps and source references. This synthetic ELF is **not actual compiled firmware** and must not be shown as hardware or DWARF qualification.

Other gated CTests are `observatory_desktop_symbols_smoke` (headless) and `observatory_imgui_symbols_ui_smoke` (Linux/Xvfb/GLFW) using the generated byte-matched fixture. Native tests do not depend on a GUI or external crypto library.

### Acceptance / limits

- Required: C++20 Windows/Linux Debug/Release builds, Windows clang-cl Debug/Release, the complete existing CTest matrix, hidden graphical smoke, and independent review of source path confinement and checksum-to-preview binding.
- **Deferred:** native ELF symbol table/DWARF ingestion, source build attestation, compiler/RTOS-qualified call/lock semantics, dynamic stack unwinding, physical target integration and any real-board/hardware tests. These are not silently counted as passed.

This is an evidence-bound foundation for W14 onward and is appropriate for offline inspection of user-supplied symbol exports, not for forensic claims without independently qualified acquisition.
